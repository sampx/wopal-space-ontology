# README 维护

创建与更新项目级 `README.md` 的权威规范。这是空间内容的公开文档工作流——每个空间都拥有项目，每个项目都可以带一份面向人类的 README。SKILL.md 正文只做路由；全部细节在此。

## 1. 使用时机

创建或更新项目的 `README.md`。README 是面向人类的项目入口文档：项目是什么、如何安装与运行、能做什么、以及持久参考在哪里。它不是 Agent 规则文件、不是实现清单、也不是设计规格。

## 2. 能力感知

本技能装配进每个空间；围绕它的文档生态随空间类型而异。更新 README 前，先检查空间实际拥有什么——绝不假设。

- 读取空间元数据：`.wopal-space/space-meta.json`。
- 用 `type` 判断空间类型，用 `capabilities.skills` 判断已装配的技能集。元数据文件缺失时，改为探测文件系统：项目旁是否存在 `docs/`？是否存在 `DESIGN.md` / `AGENTS.md`？
- **文档集对齐是条件性的。** 当空间装配了文档集类技能（如 `dev-doc-master` 或 `dev-flow`，或存在 `docs/products/` 目录树）时，README 必须与它们所拥有的设计文档保持一致。当空间未装配这些技能时，完全跳过文档集对齐——无技能空间中的 README 只需自洽并与实际项目代码匹配。
- 技能缺失是合法状态，不是错误。相关技能不存在时，忽略它本应贡献的规则，仅按下列自包含规则推进。

## 3. 语言版本与命名规则

- 项目级 README：`<project>/README.md`。
- 用户偏好语言非英文时，先在同目录创建 `README.<locale>.md` 供审核；确认后更新 `README.md`。
- `<locale>` 使用 IETF BCP 47 / RFC 5646 标签（如 `README.zh-CN.md`）。
- 正式英文版保持文件名不变 `README.md`。不生成 `README.en-US.md` 之类的英文变体。
- 偏好语言版本标题使用目标语言。

## 4. 前置条件

生成前优先阅读：既有 `README.md`、关联项目文档、项目 `package.json` / 构建 / 运行配置、主入口文件或 CLI 命令定义、license 文件或包元数据。

## 5. 核心规则

- 为人类读者写作，语气友好。
- 快速上手与核心能力放在前面；开发命令与参考链接放在后面。
- 列出模块与核心入口命令；不枚举每个子命令。完整用法指向 `--help`。
- 不深入内部实现细节或 Agent 专属实现规则。
- 技术栈与项目结构属于项目规范（如 `AGENTS.md`）与设计文档（存在时）；不在 README 中重复。
- 所有命令必须从 package / 配置文件验证。绝不猜测。
- 末尾 Technical References 承载仅参考文档（设计文档、产品文档、持久参考）。它们是信息链接，绝非强制跟随链接。不在一份文档中既出现在正文又出现在 Technical References。

## 6. README 模板

```markdown
# <Project Name>

<One-paragraph human-facing description.>

## Quick Start

```bash
<install command>
<run command>
```

## Core Capabilities

| Module | Entry Commands | Purpose |
|---|---|---|

## Development

| Scenario | Command |
|---|---|

## Technical References

| Document | Description |
|---|---|

## License

<license>
```

## 7. 写作质量线

- 用一段清晰的开场段落解释项目价值。
- 快速上手：可执行的安装与运行命令。
- 核心能力：按模块，不带实现细节。
- 开发命令：简洁表格，来源已验证。
- 技术参考：链接持久文档而不重复内容。

禁止：Agent 实现规则；深度架构解释；roadmap 重复；内部任务清单或 TODO；未验证命令或猜测的包管理器；默认放 backlog / 任务计划 / 命令转写链接。

## 8. 更新模式

1. 保留准确的用户向内容。
2. 移除过期命令与失效链接。
3. 添加或修正模块与核心命令清单。
4. 链接设计与产品细节；不重复章节。

**文档集一致性**（仅当空间按 §2 装配了相关技能时）：README 更新绝不是孤立的。模块清单与核心命令必须匹配实际项目代码，并与项目 `AGENTS.md` 及设计文档（存在时）保持一致。README 改变项目是什么或做什么时，检查它们中的过期陈述，受影响时对齐。

## 9. 确认政策

写入或覆盖 `README.md` 前，呈现完整优化方案并取得用户明确确认。方案必须包含：目标文件路径；一句话项目描述；模块 / 核心命令概览；要添加/修改/移除的章节；要引用的规范文档。确认前不写、不覆盖、不重排正式英文 `README.md`。先生成用户偏好语言版本时，先更新它，再翻译正式英文版，保持语义对齐。

## 10. 质量清单

- [ ] 目标项目根明确或安全推断
- [ ] README 是项目级，不是目录级
- [ ] 列出模块与核心入口命令，而非每个子命令
- [ ] 安装 / 运行 / 开发命令从项目文件验证
- [ ] 能力对用户可见
- [ ] 技术栈与项目结构未重复
- [ ] 持久参考已链接
- [ ] 无 Agent 规则内容
- [ ] 用户偏好语言版本先生成（非英文时）
- [ ] 用户偏好语言标题使用目标语言
- [ ] 写入前展示并确认完整优化方案
- [ ] 适用时确认后更新正式英文版
- [ ] 仅当空间装配了相关技能时应用文档集对齐（按 §2 做元数据检查）

## 11. 完成后回复

用用户语言回复：更新后的文件路径；变更摘要；已验证或缺失的命令；任何假设或缺失的持久参考；应用或跳过了哪些文档集对齐步骤（跳过时说明原因）。
