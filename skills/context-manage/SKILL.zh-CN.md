# context-manage

统一管理工作上下文的保存、跨会话恢复与压缩后恢复。三个薄命令入口只负责选择本技能中的对应工作流，协议本身只维护在这里。

## 工作流选择

- `handoff`：当前会话结束或切换前，把继续工作所需信息写入交接文件。
- `continue`：新会话读取交接文件，重建工作环境后继续。
- `recover`：上下文压缩后，根据压缩摘要重新加载关键材料、记忆和技能。

直接调用本技能时，以用户明确表达的意图选择工作流；涉及删除交接文件时不要猜测模式。

## Handoff — 保存上下文

目标文件：`<space-root>/.wopal-space/.tmp/.working-context.md`。

1. 将本次调用视为用户对**仅此交接文件**的写入授权；仍然遵守系统、工具和空间的安全边界。
2. 目标文件可能已经存在。不要先读取旧内容，直接用本次会话的最新状态覆盖它。
3. 使用可用的 shell/终端工具执行 `date '+%Y-%m-%d %H:%M:%S'` 获取本地时间，禁止自行猜测。若当前环境没有可执行命令的工具，明确记录“时间未通过系统命令验证”，不要编造时间。
4. 记录足够信息以便下一会话直接接着工作，至少覆盖：
   - 用户关切与当前目标
   - 已完成的研究、分析和关键决策依据
   - 关键发现与重要参考资料
   - 关联文件、项目路径与当前工作位置
   - 需要继续遵守的规则和约束
   - 当前进度、未完成事项和下一步
   - 若用户提供交接原因，将其一并记录
5. 写完后验证文件确实位于空间根目录的 `.wopal-space/.tmp/` 下且可读。
6. 成功后只需简短回复交接已完成；若写入或验证失败，明确说明失败点。

## Continue — 从交接文件恢复并继续

目标文件：`<space-root>/.wopal-space/.tmp/.working-context.md`。

1. 完整读取交接文件，不要只看摘要或片段。
2. 从文件中恢复：当前目标、用户关切、进度、关键决策、相关路径、规则、下一步，以及上一次会话引用的关键资料。
3. 为了恢复到与上一会话一致的工作环境，完整读取交接文件点名的重要关联文件和关键参考资料；必要时重新分析相关代码或运行可验证的检查，不要只依赖交接文本中的旧结论。
4. 若交接内容与当前文件/代码实况冲突，以当前实证为准，并在恢复摘要中指出差异。
5. 用用户偏好语言简短总结已恢复的状态，包括“正在做什么 / 已做到哪里 / 接下来做什么”。
6. 只有在上述恢复成功后，才删除交接文件。删除必须遵守当前空间的删除规则和可用安全机制；若无法安全删除，保留文件并明确告知。
7. 恢复完成后，继续执行上一会话尚未完成的下一步工作，而不是停在摘要上。

## Recover — 压缩后恢复上下文

当当前会话刚完成上下文压缩时执行：

1. 从压缩摘要中识别最重要的文件，优先选择 Plan、流程规范、设计/参考文档等；先重新读取最多 3 个，确有需要再继续按需读取。
2. 若环境提供记忆搜索能力，用 2–3 个与当前任务最相关的关键词搜索；每次查询最多取前 3 条，避免无控制地扩大上下文。没有记忆工具时跳过，禁止假装已加载。
3. 识别压缩前正在使用的技能，按当前任务关联度重新加载最多 2 个。若某技能属于强制门禁，优先恢复该技能。
4. 对涉及“系统实际行为”的结论，必要时重新读取代码控制流、配置求值或重新运行验证；不要因为摘要里曾有结论就视为仍然成立。
5. 用用户偏好语言简短汇报恢复结果：恢复了哪些关键材料、当前任务状态、下一步是什么。
6. 汇报后继续当前工作，不要把“恢复上下文”当成任务终点。

## 输出要求

- `handoff`：成功时一句简短确认；失败时说明具体失败点。
- `continue` / `recover`：先给简短恢复摘要，然后立即继续原任务。
- 不重复打印大段交接文件或压缩摘要原文。
